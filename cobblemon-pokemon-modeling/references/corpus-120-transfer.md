# 120 物种联合蒸馏：如何迁移，而非复制

## 证据范围

来源为本地 Cobblemon Forge 1.5.2+1.20.1。目的性分层选样：四足毛皮、双足身体、植物、有翼/虫类、水生/长体、矿物/幽灵六组各 20 个不同物种。分组用于覆盖不同问题，不是严谨生物分类，也不是随机抽样。未用异色或地区形态凑物种数。

- 文件级：120 组基础模型、PNG、resolver 和动画库，共 526 个唯一来源文件；另分析 36 张图层 PNG（已包含在 526 中）。模型合计 4,281 骨骼、5,309 cubes。
- 原生编辑器级：120 次隔离导入成功；每只生成绑定姿势正/侧/背/斜四视角，以及待机和移动/替代动作两个槽位。240 个槽位对应 237 段不同动画，每槽位 25 个数值采样、24 帧渲染；所有已记录矩阵有限。
- 人工观察级：120 只的联系表（模型、基础图集、四个非等周期选帧）和逐只笔记；少数代表追加完整四视角/24 帧检查。不是所有视图/所有动画逐帧精审。
- 动画文件解析：876 段目录定义，813 段匹配基础物种命名空间；其余 63 段不可无区别地当成基础骨架动画。
- 未完成游戏级验收：未验证 poser 状态混合、游戏速度/地面接触、发光着色器、粒子和音效。普通 source-over 图层首帧合成不是运行时材质证明。

本轮本地证据位于工作区 `outputs/cobblemon-distillation-120/`：`manifest.json` 为来源和哈希，`native-results.json` 为原生采样，`visual-notes.json` 为人工笔记，`records/` 为逐只汇总，`report.html` 为可视化。迁移 Skill 时无需捆绑这些原资产衍生图；若本地证据不可用，不能声称当前任务已做过同样的现场审查。

## 选择对照：按部位、材料和运动，而非只选同颜色角色

| 要解决的问题 | 可优先检查的本轮对照 | 迁移重点 |
|---|---|---|
| 毛领、尾毛、皮肤边界 | Eevee、Flareon、Growlithe、Luxray | 大体块、边缘毛片、固有花纹和局部亮簇的职责 |
| 叶面、叶根、棉团 | Leafeon、Bulbasaur、Turtwig、Whimsicott | 薄面方向、窄根宽叶、植物与皮肤分区、棉团宽色簇 |
| 翼膜、羽翼、甲壳 | Butterfree、Pidgeot、Zubat、Scizor | 像素轮廓、翼根轴心、折翼姿态、硬边与柔纹差异 |
| 石头、金属、硬壳 | Onix、Golem、Aron、Magnemite | 分节/板块边界、安静亮面、局部硬高光，不套毛流 |
| 长链、触手、软体 | Ekans、Dragonair、Tentacruel、Ditto | 绑定伸直不等于自然姿势，分节变形与身体伸缩 |
| 脸型与眼睛朝向 | Psyduck、Totodile、Aron、Gengar | 喙/颌/头面先塑形，眼纹贴合承载面；不复制表情 |

根据新角色选择少量相似部位做近景比对，而不是一次重新扫描整个语料。用户要求地面行走时，悬浮或游泳对照只能贡献局部次级动作，不能决定主体运动。

## 几何与 UV：把复杂度花在轮廓上

本轮 cube 中 2,317 个零厚度（43.64%），5,301 个整数尺寸（其余 8 个为分数），5,309 个全部 Box UV；1,598 个带非零 inflate，840 个带局部旋转。模型中位数 39.5 cubes、31 bones。这些是描述值，不是预算硬限。

- Kakuna 的 5 块、Aron 的 12 块、Bulbasaur 的 18 块和 Butterfree 的 19 块说明，外形/UV/材质协同可以胜过均匀堆叠大量细块。复杂花树、毛领或多触手可以合理使用更高预算。
- 主体用连续体积，平面承担叶缘、翼膜、羽毛等薄轮廓。不要从原版大量用平面推导“基岩版所有薄实体都应该改回平面”；用户明确选择薄立方体时保留，并验证侧面厚度、剔除和闪烁。
- 连接缺口先检查斜视和动作中的真实接合边，调整相邻块尺寸/重叠和轴心；不要以杂色贴图遮盖空洞。幽灵分离手、悬浮部件等设计性的间隔不是缺陷。
- 共面闪烁与几何空洞是两个问题：按目标材质微调层厚/间距，不能盲目把所有块一起膨胀。几何遮挡与 UV 镜像/裁切造成的“半片纹理”也要分开排查。
- 先确定头部承载眼睛的面、左右眼数量和多视角投影。侧图可见同一只眼不意味着需要额外贴一只侧眼；中央突出条或脱离头面的眼片不能代替脸型。
- 按几何实际 Box UV 展开检查共享岛和跨面方向。不要只对着图集涂好一片叶子，就假定模型每个面都能取到完整图案。

## 材质：丰富明暗不是每面固定几种色，也不是全身随机噪点

基础 PNG 色值中位数 26（统计非透明 RGBA，非单材质/单面色数）。48/120 使用 64×64；18 使用 64×32；19 使用 128×64；19 使用 128×128；只有 3 使用 256×256。Luxio 的 129×64 是已匹配模型声明的例外，不能自动裁切。

区分三层信息：固有色/标记、形体明暗、局部材质细节。先保证前两层在正常距离可读，再决定第三层密度。

- 毛：沿体积和毛流组织方向性色簇，在胸领、尾尖、毛缘重点刻画；大面保留连续中间调。Growlithe 的黑条纹是花纹，不是应被柔化的阴影。
- 皮肤：用宽而平静的色块转折，眼口周围保持高可读性；紫色并不自动意味着毛绒。耳内裸皮与同色尾毛要分材质。
- 叶片：叶轴、边缘、根部遮挡的方向明确；检查正反面与镜像后的完整性。不能拿皮毛噪声换成绿色就当叶片。
- 棉团：Whimsicott 的宽亮簇和较大暗区配合包围体积，不必每像素都画毛丝。
- 金属/硬甲：Aron 的宽白亮面、灰面和黑孔已能表材质；高光边界可比毛发更硬，亮点不要均匀撒满全身。
- 岩石：Golem、Onix 的板块/岩节边界和成簇斑驳服务几何；不同块不要用完全独立的随机噪声造成拼贴感。

“丰富到几种颜色”只能作具体 A/B 的审美约束，不能从整张图集的色数推导每面必须至少 N 色。旧样板的 256 图集和高密纹理不自动成为新资产默认值。先选能承载眼睛、标记和最细必要纹理的分辨率，再验证像素密度一致性。

23 个基础 resolver 带图层；基础图只有 Flareon、Magikarp 两例含部分 alpha。不要由基础 PNG 大多二值透明推断效果图层都必须二值。图层原语义、逐帧顺序、emissive/translucent 接线分别核验。

## 动画：观察窗、周期和行为状态必须分开

470/876 段含表达式，437 段未显式声明 `animation_length`。无声明不等于静态或损坏。采样工具依次用正数声明时长、最后关键帧时间、2 秒回退窗口；后两者尤其不能当成已知周期。

- 简单 `math.sin(q.anim_time * k)` 在 Molang 中角度为度，未再改速时周期为 `360/abs(k)`；多个频率、abs/clamp、状态项共同决定整体周期，需要组合分析。不要用 JavaScript 默认弧度重写后直接比较。
- 绑定姿势、单动画预览、poser 混合后姿势分开呈现。Ekans/Onix 的伸直链、鸟类的平展翼、双足的展开臂均不是自然姿势的直接证据。
- 接地动物先确定支撑、摆动和真实脚底，再配躯干、头、尾/耳/叶的次级运动；完整动作不等于所有骨骼同幅摆动。不能把水生、幽灵的悬浮直接移植给用户明确要求行走的角色。
- 四足前后相位根据所选对照和用户偏好制定。历史项目的“后脚提前约 0.088 秒”只属该项目，不是叶伊布或全语料的通用规律；应调整同周期内的相位，不改变单条腿频率造成累积漂移。
- 首尾矩阵差只比较当前采样窗口端点；窗口不是完整周期时非零差不证明循环接缝。稀疏四帧可能落在相同相位，需看全帧或非等周期帧并结合轨道数值。
- 本轮原始比较有 75 段未匹配骨骼引用，限基础命名空间后仍有 50 段。这是引用审查线索，不是 50 个已证实游戏错误；例如 Quilava `fire_back`、Jolteon cry 的 `mouth/tail` 要核查实际状态、形态和代码。
- Poliwag/Poliwhirl 的 `v.foot` 出现在 `foot_left/right` 轨道，而所选基础模型没有这些足骨；检查过的片段没有就地赋值。不能从导入后矩阵有限推出变量已正确赋值，也不能据此断言基础角色脚部在游戏里坏了。必要时追查 poser/代码上下文，而不是给所有变量自动填零。

## 可复用批量流程

先读当前项目状态并保护未保存内容；原资产只读，研究输出放在原目录之外。三个脚本位于本 Skill 的 `scripts/`，需按当前环境提供绝对路径。

1. Python 3 + Pillow 执行 `analyze_corpus.py --root <解包根目录> --out <研究输出>`。它选择预定义分层名单里资源齐全的不同物种；低于 100 会失败，缺失名单保留于 manifest。更换版本后重新看分组计数，不假定永远各 20。
2. 通过 Blockbench MCP 加载 `inspect_corpus_blockbench.js`，先设置 `window.CB_STUDY_OUTPUT` 为输出绝对路径。脚本依赖桌面版 Node 文件访问及当前 Blockbench API；先小批试运行，不假设跨版本兼容。
3. `cbStudy.run(start,count)` 逐只建空审查工程、导入内部贴图副本、加载动画、渲染并逐只写检查点，再关审查工程返回原项目。不要并发运行同一编辑器的写操作，也不要重跑已成功样本。重启后读取 `native-results.json`，按 manifest 索引仅补缺失/失败项。
4. 异步执行后查看 `cbStudy.status` 和磁盘结果，不把工具返回理解成批次已完成。纹理必须等原生 load 回调，后台计时器可能被 Chromium 大幅节流。运行中不要让用户在审查项目中编辑。
5. 用 `build_corpus_report.py <输出> --contacts-only` 生成联系表；实际查看后通过补丁填写 `visual-notes.json`，不能由统计数字自动声称人工目检。报告数量由实际数据计算；增量排除旧样本、条件图层与形态前缀处理见 [corpus-200-extension.md](corpus-200-extension.md)。
6. 不带 `--contacts-only` 生成报告和逐只记录。用 `analyze_corpus.py --root <根> --out <输出> --verify` 比对来源哈希；再检查 native 成功数、有限矩阵、图像/记录/笔记数量、活动原项目。清单的 `visual_status: pending_native` 是文件扫描阶段快照，最终状态以 native 结果和人工笔记为准。

脚本保留为可复用工具；原模型/PNG/动画不放入 Skill。分发研究截图需保留 `licenses/` 中原许可及来源说明；公开发布前另核对资产与角色权利。
