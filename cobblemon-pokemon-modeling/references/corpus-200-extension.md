# 新增 200 物种：条件外观、命名空间与动作覆盖

这是 [120 物种方法](corpus-120-transfer.md) 的补充，不替代前一轮证据，也不重复统计同一物种。

## 样本与证据

仍为本地 Cobblemon Forge 1.5.2+1.20.1。排除前 120 只后，从资源齐全的 507 个候选物种中，按图鉴号排序等间隔选出 200 只；这是确定性扩展样本，不是随机抽样，也不是上一轮六种体型各等量抽样。合计覆盖 320 个不同物种。

- 新样本：8,448 bones、10,264 cubes；模型中位数 37 bones、44 cubes。4,849 cubes 为零厚度（47.24%），10,242 个整数尺寸，全部 Box UV。
- 200 张基础图集色值中位数 25；另查所有同物种 resolver 的图层引用，共 134 张唯一图层 PNG（包含基础分支的 34 张），546 条 variation。26 只的基础分支有图层，24 只具有非空 aspect 的图层分支；两组有重叠。
- 200 次原生导入全部成功；每只两观察槽位，共 400 个槽位、393 段不同动画，25 个数值时刻/24 帧。132 个移动槽位选到 walk/swim/fly 命名动画，其余 68 为替代观察；没有对应文件不代表游戏里没有行走。
- 文件级解析 1,334 段目录动画：694 含表达式、587 未声明时长。150 个原生观察槽位用声明时长，250 个用 2 秒回退观察窗，不能当真实周期。
- 人工查看 20 张联系表的全部 200 只，并写逐只笔记；部分追加完整动作帧表或四视角。不是对全部 1,334 段逐帧精审。
- 980 个来源文件记录哈希；两次形态动画重采和两组显式红花图层对照单独记录。原模型/PNG/动画只读，不把原资产装入 Skill。

本地证据目录为工作区 `outputs/cobblemon-distillation-200/`，具有 manifest、summary、native-results、visual-notes、records、report、supplemental 和 backup。图像成功导入仅证明可渲染，不证明 poser、材料着色和接地行为已通过游戏验收。

## 1. “没花瓣”可能是条件图层，而不是缺几何

花蓓蓓和花洁夫人的 `aspects: []` 基础分支没有花色图层；`flower-red` 等条件分支才提供花朵纹理。本轮保持几何不变，显式加载红花层后，缺失的花瓣/花冠在原生渲染中出现。

遇到缺失部位时，依次区分：几何不存在、UV/alpha 没有取到可见像素、条件图层未加载、动画缩放/姿态隐藏、运行时材质/剔除差异。不要只查最先找到的空 aspect variation 就补块或重绘透明区。

需读同物种全部 resolver 文件的 `order`、`aspects` 和覆盖字段；原样记录条件 token，不把空格连写的 aspect 擅自拆成多个，也不假定多个条件同时满足。显式对照使用已存在的某个 aspect，并标明“研究选择”，不能冒称默认游戏状态。

Smeargle 尾端颜色、Conkeldurr 部件着色、Dubwool 染色等也说明，普通非发光颜色可以来自条件层。不能将“layers”仅理解成火焰/光效。

## 2. 物种名、资源名、内部 geometry 标识和动画前缀不能互换

| 例子 | 本轮读到的实际关联 | 应改变的判断 |
|---|---|---|
| Mr. Mime | 物种 `mrmime`，模型/动画 `mr_mime` | 字符串不相等不代表缺动画 |
| Oinkologne | 空 aspect 指向 `oinkologne_male.geo`；同目录另有雌性动画 | 不取目录中碰巧排前的雌性待机 |
| Maushold | resolver 指向 `maushold_three.geo`，内部 identifier 却为 `geometry.maushold_four` | 先跟踪 resolver 所选资源，再用骨骼与形态核对；不按内部标识盲选 four 动画 |
| Gimmighoul | 基础为 `gimmighoul_chest.geo`，库中也有 roaming | 宝箱与徒步形态不可混用动作 |
| Rattata 等 | 性别模型后缀 `_male`，动画共享无性别物种前缀 | 没有 male 前缀不代表没动画 |

200 只中有 20 个资源名不同于物种名的例子，16 个没有同名模型动画前缀而共享物种前缀。原生采样器现在优先 resolver 模型资源前缀，再尝试共享物种前缀；全库兜底必须标注未解决并人工审查，不能视为自动正确接线。

这些是候选选择规则，不是 Cobblemon 引擎强制命名法。最终还要核查 poser、状态名与骨骼映射。对原语料中未匹配骨骼仅报证据，不自动删除轨道或重命名骨骼。

## 3. 动画目录不是完整的运行时行为清单

不少物种的目录仅含待机、blink、cry、pose；Lillipup 甚至在所选目录没有 idle，Jellicent 的所选命名库为 render/blink。采样器能生成两张帧表，不意味着生成了待机加行走。

- 报告显示实际 clip 名称、是否替代槽位和是否重复。同一条动画占两个观察槽位只算一段不同动画。
- 不以展开的手臂或长直附肢判定游戏缺动作。绑定姿势、静态 pose、单条循环和 poser 混合分开验证；未经接线证据不自行叠加所有 pose 来制造“自然截图”。
- 新建用户资产仍须实现用户要求的完整行走与待机。原语料里缺少 JSON walk 不能用来合理化省略新项目的手臂/身体动作，也不能为行走角色改成漂浮。
- Mudbray 可观察四足跨步与头身关系；Thwackey 可观察双足与臂部协调；它们是动作关系的对照，不是统一相位数值模板。

## 4. 图集总色数和整模包围盒都有统计盲区

- Rattata 基础图集中可见文字区，多个图集还有孤立色条；未做实际 UV 覆盖分析前，不应把所有非透明色值称为“角色表面用色”。当前脚本统计的是整 PNG，不是可见面调色板，也不是每面色数。
- Luvdisc 为 16×16、7块、7色；Pineco 35块但8色；Wailord 33块却512×128；Ursaring 96×96；Florges 180块、Skeledirge212块。这些例外支持“按轮廓、材质与 UV 容量预算”，不支持固定分辨率或几何/色数线性关系。
- 道具和伸直附肢会主导包围盒：Tinkaton 巨锤、Sirfetchd 葱剑盾、Dhelmise 链条、Whiscash 长须。正常尺寸/头身比例的观察要另取主体边界与规定姿势，不能按整体缩略图占比直接缩放角色。
- 全部帧共用镜位便于动作对比，但绑定包围盒未必覆盖动画极值；发现道具出画面时补更宽镜位，不把裁切误报成几何消失。未补拍的裁切不能算相应部位全程验收。

## 5. 多个子体和持物不是普通肢体模板

Exeggcute、Falinks、Maushold 是多个子体组成一个角色；应保留子体根与相对队形，不能把全部眼睛误当重复五官。先从参考确认设计的个体数，再判断骨架和纹理是否对应。

Conkeldurr 石柱、Komala 抱木、Tinkaton 锤、Farfetchd/Sirfetchd 葱为持物关系。手与道具在绑定姿势中分离不一定是接缝问题；先看握持动作中的实际相对变换。制作新角色时，持物接触、肩臂可达范围和重心优先于全身自由摆臂。

## 增量分析命令与保护

先保留旧 Skill 和旧报告；输出到新的研究目录，不覆写旧轮证据。

```text
py -3 -X utf8 scripts/analyze_corpus.py --root <原资产> --out <新输出> --additional-count 200 --exclude-manifest <上一轮manifest>
py -3 -X utf8 scripts/analyze_corpus.py --root <原资产> --out <新输出> --enrich-existing
```

`--exclude-manifest` 可重复用于排除多轮。扩展取资源完整候选按图鉴等间距选择，不承诺每种材料都均等覆盖。`--enrich-existing` 先核验现有哈希，再追加同物种 resolver 条件和条件图层证据；其中模型替代资源、异色底图没有自动全部视觉审查，不能夸大覆盖。

原生批次、联系表/笔记、报告和 `--verify` 流程沿用前文。报告现从实际结果动态计算数量，不再写死120。采样命名空间变更只重采受影响项；补充 aspect 对照存 `supplemental/`，不额外计入不同物种数。

批量完成后验证集合去重、PNG 和记录数量、矩阵有限性、原文件哈希及原活动项目快照。脚本检查通过和编辑器帧表都不替代游戏内验收。
