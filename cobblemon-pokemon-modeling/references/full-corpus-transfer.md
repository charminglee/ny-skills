# 全库覆盖与行为接线：1.5.2 实证补充

本轮在旧 320 物种及专项研究基础上扩展到本地安装包的所有模型资源，而不是新增 763 个物种。证据位于工作区 `outputs/cobblemon-full-20260922/`；不将原模型/PNG/动画装入 Skill。

## 覆盖和边界

- 763 个 geometry：633 个编号物种目录及 1 个非物种辅助项 substitute，包含性别、地区、季节与其它形态。38,490 cubes，其中 17,503 零厚度；31,194 bones；模型中位数 43 cubes、35 bones。这些不是制作预算硬限。
- 1,957 张 PNG、676 个动画文件/4,250 段定义、758 resolver/1,768 variation。760 个模型有本轮解析到的贴图绑定，另 3 个中性预览。
- 763 个原生导入/静态视图成功；4,261 个模型-动画组合采样，对应 3,846 段不同来源片段，404 段尚未渲染。已采样矩阵均有限，不代表 poser/循环/接地正确。
- 32 张四视角联系表全部浏览，4 个材质近景与 8 个动作表追加观察。普查不等于 763 个逐像素精审，也不等于 4,250 段逐帧验收。
- 160,860 条有效 UV 面记录包含隐藏/内部面；其中 29 条越界待运行语义核查，不能称为 29 个已证实可见 bug。面采样色数中位数 3 不支持“每面只能 3 色”，也不支持“每面必须更多色”：面面积、透明、遮挡和特征职责会改变统计。
- 3,123 条 class 常量池索引只用于定位代码。已读的方法证据是 QuadrupedWalkAnimation、BipedWalkAnimation、SingleBoneLookAnimation 的 setAngles，以及 Leafeon/Poliwag/Psyduck 的 registerPoses；不是所有 poser 已逆向。
- 原文件 7,807 份哈希复核未变化。未运行游戏；全部渲染为编辑器绑定姿势或隔离单动画，不能证明完整材质/状态混合。

## 本轮应改变的决策

### 贴图绑定必须包含跨 resolver 继承

Venusaur 的基础 resolver 提供贴图和雄性几何，雌性 resolver 仅覆盖几何。若只看单文件，雌性会被错误渲染为灰模。按同物种文件 order 应用无条件默认字段，再审查所选条件覆盖；记录明确来源。此简化解析仍不等于所有条件同时组合的运行时规则。改变绑定时，缓存键不仅看 geometry 哈希，还要看实际贴图/图层/分支，不能复用旧灰模证据。

Vivillon、Florges 等基础分支缺少完整外观的情况继续适用 [条件图层检查](corpus-200-extension.md)。先排查分支、alpha、姿态隐藏，再推断缺模型。

### 状态名不等于片段名

Leafeon registerPoses 中 standing 绑定 ground_idle，而 walk 的 MOVING_POSES 绑定 ground_run；所以“参考叶伊布走路”不能只读 ground_walk。Psyduck 的 walk 则绑定 ground_walk，并另有 FLOAT/SWIM。需要先定位该版本实际注册，再研究对应片段与混合，不用名称猜游戏行为。

通用 BipedWalk 与 QuadrupedWalk 的代码是带幅度/权重的加法旋转，前者两足相差 π，后者按对角配对；只表示这些辅助类的实现，不证明每只物种都使用它们。SingleBoneLook 对 pitch/yaw 先限制范围、乘倍数、转弧度再按权重添加，因此孤立 JSON 预览可能缺少运行时看向目标动作。不要把 Java 代码弧度与 Molang 正弦的度制混用。

### 大小/材料分层，不能只积累更多色卡

Psyduck、Mareep、Whimsicott、Roggenrola 的同镜位无光照/有光照对照支持：先决定整体明暗、固有标记和材料结构，再在 UV 面上落实；编辑器灯光不能补偿底图失去结构。

- 蓬松鸭/小鸟：主要体块与喙、翼、脚优先。宽亮胸区，柔软但稀疏的边缘羽簇，五官周围不铺随机碎斑。
- 羊毛/棉团：宽中间调、团状亮簇与下缘暗区；不同团块有联系但不完全重复。不能用一圈圈同心高光代替整体体积。
- 岩石/金属/晶体：大安静面与局部硬边，晶面按方向分亮暗；不移植毛丝纹或把每个面随机加噪。
- 蘑菇/植物/薄翼：帽顶与帽底、叶轴与叶根、翅纹与翼膜分别设计；正反面和裁切要现场看。
- 小型精灵：眼形与主色分区优先于细毛，少量必要像素即可；按自身比例决定头形，不能把狐狸棱面眼或大体型纹理密度泛化。

已有 [整体重绘](whole-form-texture-shading.md)、[大体型材料](large-creature-materials.md)、[眼睛](eyes-and-expression.md) 继续适用，不被本轮统计取代。

## 批量制作迁移

每只保留参考来源、可见结构、推断背面、材质分区、主体大小、运动类型和所选对照。共享的是导出/渲染/数值验证工具，不是换颜色的同一骨架。先小批验证，再按个体轮廓制作；静态立绘跳起或展开不自动意味着漂浮移动。公开百科的体型区间可以选中值作为项目尺度约定，但要注明，不伪称官方唯一比例。

先制作材料样品，随后按整模型结构重绘，最后用固定视角关闭/开启灯光验证。眼睛要单独在正面、侧面和正常距离检查。完整动作包括有依据的主体、附肢和次级动作；数值合格仍须看图和播放。

## 可复用全量工具

`scripts/distill_full.py prepare --root <源目录> --out <新证据目录>` 建立关联索引；`verify` 复核只读来源。`scripts/distill_native.js` 通过 Blockbench MCP 加载前设置 `window.CB_FULL_OUTPUT`，小批确认后调用 `cbFull.run(start,count)`，同一编辑器禁止并发写入。输出阶段需人工观察和归纳，不由脚本自动声称美术通过。备份保存到原资产以外，图层首帧 source-over 只是观察便利，不是运行时着色器。

`scripts/class_evidence.py <class> --method <方法片段> --out <json>` 是有限的静态反汇编辅助，不执行来源 class，不恢复源码或完整控制流；分支操作数为原始偏移。引擎混淆调用未查映射时保留原符号，不猜函数名。
