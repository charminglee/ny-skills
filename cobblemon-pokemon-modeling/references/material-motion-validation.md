# 局部材质与动作验证

用于把语料观察迁移到新角色时，区分“观察到的做法”“本模型上验证的约束”与“尚待用户确认的审美”。以下经验来自 Cobblemon 1.5.2 的五例只读分析及 Plumeleaf 独立样板，不是全语料的统一艺术规范。

后续扩展的 120 物种证据与对照选择方法见 [corpus-120-transfer.md](corpus-120-transfer.md)。原样板上通过的更密纹理、薄实体块或后脚领先时差不自动成为所有新角色的风格要求。

## 局部材质 A/B

- 先取有代表性的毛发、羽片或叶片做局部对照，在同几何、同 UV、同姿态、同镜位、同光照下比较。不要同时改变所有变量，再把改善归因于贴图。
- 绘制前按实际面 UV 查找共享岛。重绘共享区域可能改变未点选的部位；若必须独立处理，另行分配 UV 并验证，不可默默连带修改。
- 分别检查图集原像素、材质局部与整个角色。方向性色块可以说明羽轴、毛流或叶脉，但不能修复几何叠层、轮廓或绑定姿势的问题。
- 局部样品成立不代表全身成立。初贴后按 [whole-form-texture-shading.md](whole-form-texture-shading.md) 检查连续体积、接缝两侧色阶与视觉焦点；使用关闭/开启编辑器光照的同条件 A/B 分离贴图本身和预览灯光的作用。
- 小眼睛 UV 并不必然低质量；先看层叠几何、明暗组织与正常距离的可读性。遮挡式眨眼也可有效，需检查覆盖范围、轨迹和时序。
- 单个样板的色数、色值、分辨率或像素簇形状不能直接升级为通用规则；视觉偏好需要用户验收。

## 步态验证

- 区分支撑段与摆动段，先确定接触轨迹，再安排骨盆起伏、脚踝补偿和次级动作。所有骨骼同时摆动不等于自然动作；也不必给每个尾段强制添加递增延迟。
- 测量脚骨骼下包括脚爪在内的实际几何下边界，不只看骨骼轴心。现有 cube 旋转和 inflate 会让几何低于名义脚底。
- 精确测量 cube mesh 的实际 position 顶点并乘完整 matrixWorld。`Box3.setFromObject` 可能遍历到不可见的选择轮廓子对象；几何缩放后这些辅助缓存会污染高度/脚底测量。异常数值先排除 gizmo 和隐藏轮廓，不因此修改已正确的形状。
- 检查关键帧间采样、左右相位和循环首尾，不只截取动作极值。明确测量使用精确顶点、包围盒还是 pivot；包围盒结果不是碰撞接触解算。
- 支撑段模型空间的后移速度须与目标移动速度及模型缩放匹配。原地预览落脚高度稳定，只证明编辑器约束，不证明游戏内无滑步或穿地。
- 制作时可用 IK 解算并烘焙普通关键帧，但不应声称因此获得游戏实时 IK。周期、步长、支撑比例和摆幅根据角色决定。
- 四足“逐脚挪动”“对角过度同步”与“后脚先落地”是不同问题；用落地事件差、实际运动方向与脚底轨迹判定，按 [full-body-animation.md](full-body-animation.md) 调整，不通过改变单腿循环频率制造长期漂移。
- JSON 动画未必包含完整行为；检查 poser/代码动画与混合。无某条骨骼轨道时，不推断运行时不会运动，也不擅自合成未证实的状态叠加。

## 独立样板与现场保护

- 存在未保存编辑时，以现场快照为基线，保留原项目，不用较旧磁盘文件覆盖它。测试贴图解除原路径关联，避免保存或跨项目同步到原图。
- Blockbench codec 的 parse 可能向已有项目追加内容。导入副本时使用空项目，并检查元素、骨骼和动画数量；重复 UUID/骨骼会造成动画变换重复应用。
- 多工程并存时，每次写入和导出显式选择并核对目标 Project UUID；不要假定前一调用的活动标签仍然有效。跨工程不复用绑定到旧 cube/bone 的缓存引用，按当前工程重新解析。
- 先发现原生只读 MCP 工具。某些 bbmcp 版本的 risky_eval 即使只读也会建立撤销条目，隔离试验更安全。
- 批量脚本报错后检查真实工程状态、元素/关键帧数量和关键参数。工具可能自动回滚，脚本建立的 window 辅助变量却仍存在；辅助变量或最后输出不是变更成功的证据。大对象输出只摘取标量/计数，完整工程写入备份，不在日志中打印贴图或数千个关键帧。
- 动画预览顺序为设置当前动画/时间、更新姿态、更新世界矩阵、最后固定镜位。不要在 Animator.preview 后再调用会恢复绑定姿态的全量更新；绑定尺寸修改后则需刷新骨骼变换与默认姿态再量测。
- 验证后导出并重读模型、PNG、动画，保留可恢复快照和必要对照证据。原始资产不改；测试报告、可编辑样板属于交付物，不按临时垃圾删除。
