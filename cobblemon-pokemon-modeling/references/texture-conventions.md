# 贴图约定

## 像素语言

- 使用清晰的像素簇，不做抗锯齿、插值缩放或随机噪点。轮廓、材质和受光关系比颜色数量更重要。
- 从中间固有色建立少量亮部、暗部和强调色。大面保持可读色块，用有限纹理簇说明皮毛、鳞片、羽毛、植物或岩石材质。
- 贴图图集在透明背景上组织 Box UV 岛。边缘像素必须干净，避免半透明脏边和无意颜色泄漏。
- 不以“固定 22 色”作为规则。语料中位数约为 22 色只是风格参考；复杂花纹、复合材质或大型模型可以合理增加色阶。
- 整 PNG 的色数可能包含未被实际 UV 使用的文字、色条或备用区域；未检查 UV 覆盖前，不把它称为可见表面色数。新增 200 样本中位数为 25，不能据此规定每面必须几色。

## 材质分区与手绘体积

- 全身材质初贴不是完成态。读 [whole-form-texture-shading.md](whole-form-texture-shading.md)，增加按整体结构重绘：先组织连续形体上的大明暗，再安排方向性色簇与跨面过渡；样品裁片仅作起稿，不能独立决定每面的亮暗。
- 用户要求丰富明暗时，不把每面限制为三色，也不以增加颜色数量代替材质塑造。先组织固有色、主亮暗面、连接处阴影，再用有方向的像素簇表现材质；避免各面重复同一条纹或随机撒点。
- 按材质而不是按颜色分区：同样的紫色可能分别属于皮肤、毛绒尾巴、叶片和耳内皮肤，不能统一套用毛发纹理。
- 毛发：沿毛流组织不等长的束状亮暗簇，留出安静的大色块；束间暗部与亮部可有冷暖变化，但不是所有物种都必须暖亮冷暗。推广到全身时按头、毛领、手臂、腿、尾巴各自方向调整。
- 皮肤：用连贯的大色块和较克制的阶梯过渡表现体积，避免毛发式碎纹。耳内属于皮肤时，检查左右内耳及耳尖，结合凹面安排边缘/根部暗部和中央亮部，不遗漏小区域。
- 毛绒尾巴：沿尾段与毛团方向绘制，不把既有深色环纹整体提亮或抹掉；区分花纹固有色和受光阴影。
- 叶片：以中脉、侧脉、根部和边缘组织亮暗，检查中脉两侧都有所需纹理；正反面、左右镜像、头顶长叶与身体绿叶分别核对。不要把毛发模板直接复制到叶面，也不要靠改变透明轮廓掩盖半边漏画。
- 局部重绘先从实际 UV 建立目标像素集合，记录共享岛；对比修改前后，检查目标区域外像素及 alpha 是否保持不变（任务未要求改它们时）。工程内嵌 PNG 与独立导出 PNG 应一致。按任务保留眼睛、爪子、花纹等非目标区域。

材质分区方法来自 Plumeleaf 迭代；整体结构重绘另有 320 物种专项支持，证据边界见其引用。二者都不是 Cobblemon 全语料的统一配色或纹理模板。先局部 A/B 确认方向，再按用户授权推广。

## 尺寸与采样

小型精灵的单面像素预算，以及“材质样品 → 小面取样 → UV 初贴 → 整体结构重绘”的狐狸流程迁移，见 [small-creature-budget.md](small-creature-budget.md)。低密度不等于每面固定三色，不能只缩图集而保持旧的高密度设计。

- 从 64×32、64×64 或 128×64 一类较小图集开始预算；只有细节、物种尺度或 UV 容量确实需要时提高到 128×128、256×128 或更大。
- PNG 实际尺寸必须与 geometry `texture_width` / `texture_height` 一致。
- 使用最近邻预览与缩放。重排 atlas 时等尺寸搬运像素，不用双线性插值。
- 普通、异色及同一 geometry 的覆盖层保持相同画布尺寸和 UV 对齐。

## 普通与异色

- 普通形态先确定材质分区、明暗层级和辨识花纹；异色在同一布局上重映射色相与色阶。
- shiny 不等于全图统一色相旋转。保留眼睛、口腔、角爪、火焰、金属等材质之间的关系，并依据物种设定决定哪些区域变化。
- 性别、地区、季节和图案形态若只改变表面，优先共享 geometry 并由 resolver 选择贴图；轮廓或运动发生变化时才使用独立 geometry。

## Alpha 与图层

- 普通底图的可见像素默认使用完全不透明 alpha，背景使用完全透明 alpha。
- 半透明仅用于明确材质，如薄翼、幽灵体、烟雾或柔和发光。不要为边缘抗锯齿引入半透明像素。
- 发光部分放在独立 emissive 贴图/图层；需要透明叠加时同时在 resolver 标注 translucent，并检查不同视角的排序。
- 火焰、光晕和循环图案可使用等尺寸逐帧 PNG；每帧保持相同 UV 布局、命名顺序和透明语义。
- 图层贴图只绘制该层负责的像素，其余区域保持透明；不要复制完整底图造成重复着色。

## 视觉检查

### 脸部与眼睛

新增/重画眼睛、修复神态与设计眨眼时，先读 [eyes-and-expression.md](eyes-and-expression.md)。该专项区分头部眼纹、平面眼、转角眼、侧眼和分层瞳孔，并记录用户否定的迪莫模板；不以颜色数量或像素分辨率作为眼神验收标准。

- 先根据参考判断细竖瞳、圆瞳或横瞳，不把少量紫色像素随意排成横条。黑色轮廓不应默认围成矩形“眼框”；用皮肤/毛色角区和有意的像素阶梯组织参考眼形。
- 左右眼可以镜像复用，但需在实际斜脸上检查外眼角方向、瞳孔方向和高光；相同 UV 数字并不能证明视觉对称。保持项目像素尺度，不局部提高眼睛密度来逃避形状修正。
- 更改眼面尺寸或倾斜后同步检查眼睑的开、合及中间姿态。沿正确脸面法线覆盖，避免闭眼仍露虹膜、睁眼露眼睑边或眼面共面闪烁；需改哪些眼睑轨道由实际变化决定。
- 同时查看正常观察距离和近景；脸型与眼形一起判断，不能以颜色数或单张图集截图代替神态验收。

在 Blockbench MCP 中同时检查 atlas 原图、关闭/开启编辑器光照的模型近景和正常游戏观察距离。灰度只辅助诊断大明暗，彩色仍要确认材质与固有花纹。重点查看眼睛与脸部、左右方向、接缝、旋转平面、透明边缘、普通/异色切换、发光与半透明叠加。
