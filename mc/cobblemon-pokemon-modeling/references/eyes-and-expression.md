# 眼睛专项：承载面、像素职责与神态

用于制作眼睛、修复“眼睛不像/呆/凶过头”、安排眨眼，或进一步研究原模组眼部。与 `texture-conventions.md`、`reference-reconstruction-and-scale.md` 配合；本文不是可直接套用的眼睛贴图模板。

## 证据与适用边界

本地 Cobblemon 1.5.2 的 24 只专项样本：伊布系 8 只（不含火伊布）、Shinx、Luxray、Zorua、Pikachu、Bulbasaur、Charmander、Squirtle、Riolu、Lucario、Treecko、Gengar、Meowth、Ralts、Braixen、Sprigatito、Meowscarada。它们从原 320 只中复选，不计作新增物种；选择偏向脸部比较，不代表全库分布。

证据目录 `outputs/cobblemon-eyes-study/`：manifest 含来源/哈希，native-results 含实际面 UV、结构及眼睑变换，24 张眼部四视角/眨眼联系图和 24 张 UV 候选图，逐只人工笔记、图层覆盖记录及报告。完成 96 个近景视角槽位、22 段匹配 blink 各 5 时刻；Ralts 追加头发遮挡对照。不是 22 段连续播放、poser 混合或游戏级验收。Skill 不携带原贴图、几何或衍生截图。

## 先分辨结构，别先画统一黑眼睛

| 结构 | 本轮实例与证据 | 建模决策 |
| --- | --- | --- |
| 头部贴图里的眼睛 + 独立眼睑 | Charmander 的睁眼画在 head 正/侧面，模型只有 eyelid 骨骼 | 找不到 eye 骨骼不代表没有眼睛；从实际头面 UV 查找 |
| 前向单眼面 | Eevee 2×3×0；Pikachu 2×2×0；Sprigatito 3×4×0 | 简单眼面可以成立；不默认加厚眼框、鼻梁托板或高分辨率眼片 |
| 跨头部转角的眼体 | Jolteon 1×2×3；Bulbasaur 2×3×2；多只伊布为 2×2×1/2 | 前面与侧面是一只眼的连续部分，不能各画一套完整眼睛 |
| 侧向眼 | Treecko 的眼面 X 为零，主要朝向左右 | 正视看不见完整眼睛可能正确，不擅补前眼 |
| 眼白/虹膜/瞳区分层 | Shinx 的 2×3、1×3、1×1 层；Meowscarada 的 3×2、2×2、1×2 层；Riolu 有 pupil 骨骼 | 需要独立视线、表情或遮挡时再分层；不把所有层都当独立眼睛 |

尺寸是实例，不是新角色的固定预算。Gengar 的 7×7 眼面也有效。零厚度源资产说明其结构方法，不覆盖用户对基岩版薄实体的明确选择；目标游戏仍需剔除与叠面检查。

## 先确定眼神，再量化像素

从用户参考标出：眼区外轮廓、内外眼角高度、上缘弧线/斜压、下缘饱满程度、眼距、眼高占脸高比例、瞳孔长宽与视线、露出的眼白、虹膜色区和亮点位置。使用同一视角测比例；不同透视截图不能直接比较屏幕宽度。

将这些职责分开判断，不意味着每项必须存在或独立建骨骼：

- **眼区/眼白**决定眼球露出的范围；亮色整条区域可能是眼白，不一定是高光。
- **虹膜**围绕或邻接瞳孔维持原本的色彩结构；不要默认只在最底端画一条彩色横带。
- **瞳孔**决定视线和眼型：圆/竖瞳/其他形状按参考选，不靠一个通用黑块替代。
- **上缘、眉部、面罩**影响神态但不等于瞳孔。Luxray 有额部压眼的几何贡献；Zorua 眼骨骼 Z 轴约 ±10°；Pikachu 约 ±3°。不能用大面积黑三角代替所有角色的锐利上缘。
- **高光**用参考所需的少量簇即可；位置应相对瞳孔和光照/设计关系核对，不机械镜像或两眼各自随意放角落。

先选与整模一致的像素密度，再在实际可用格数里保留最重要的形状。Eevee 的 2×3、Pikachu 的 2×2 表明更多像素不是前提；Gengar 与 Sprigatito 表明有必要时也可增加轮廓信息。不要把“眼睛不能矩形”或“必须有眼白”写成通用禁令，原模组两者都有反例。

低像素版保留的是外轮廓与各区域的关系，不是把高分辨率圆眼简单最近邻缩小，也不是统一给所有眼睛加粗黑描边。圆眼配斜上缘应同时保住下缘体积；外眼角尖并不等于整个眼球是尖三角。

## 三维承载与 UV

眼面方向先服从参考脸型。先验证斜脸、口鼻突出与遮挡，再画最终眼纹；不要将平面眼贴在与参考不符的正面方板上，用纹理细节掩盖脸型问题。

至少比较正面、斜侧、两侧；逐眼追踪瞳孔和高光，确认是同一只眼随视角变化，而非镜像反了、侧面多出瞳孔，或前眼与侧眼断开。源资产中 Eevee 纯侧面看不到眼睛、Jolteon 侧眼面积大，都不是自动缺陷。

不要把 Box UV 展开的所有候选图块都叫“可见眼睛”：其中可能包含眼睑、眼白、隐藏背面、表情替代层。计算可见配色或眼区比例前先定位实际承载面；只匹配名字会漏掉 Charmander 的头部眼纹。

左右共享 UV 前检查：眼角倾向、眼白朝内/朝外、竖瞳方向、高光相对位置。调整眼面角度/尺寸后复查映射和眼睑，避免厚眼片边缘露出、串色、拉伸或共面闪烁。源实例的 0.01/0.02/0.03 inflate 是分层证据，不是可不经缩放和渲染验证照搬的毫米级配方。

## 独角精灵：单块头的跨面眼与尺寸反馈

- 小型马类先考虑简洁主头块，不为让正侧面都看见眼睛而默认套用狐狸的外张斜脸块。独角精灵早期厚脸颊使眼睛像凸出的鱼眼，用户明确否定；这是承载几何问题，不是仅调瞳孔颜色可解决的。
- 原模组马类的侧向眼只是参考，不应变成“这只必须仅侧面画眼”的限制。用户后来明确要求正面和侧面共同绘制：将一只眼纹连续分配到同一头块的前侧转角，保持两个眼睛，不在两个面各画一套完整瞳孔。
- 同一像素数在不同脸部大小上观感不同。用户曾认为旧脸上的 3×3 眼区过大，且眼白接近皮肤；先核对占脸比例，再安排像素职责。暖白皮肤可用冷灰紫眼白拉开差异，但需同时检查明度和正常距离辨识，不能只依赖色相差或粗黑描边。
- v4 使用每只眼睛正面 2×2 + 侧面 1×2，共 6 个连续像素，配适度放大的主头块。这是一次实现，不是用户已验收的通用眼睛模板；4–10 像素方向仍需服从眼型、视线与角色大小。
- 跨面后同步补齐前、侧眼睑。若一根骨骼驱动两片正交覆盖面，位移需同时满足两个面法线方向，并留足移动后的内眼角、后眼角覆盖余量；不要只沿侧向推出，造成正面闭眼仍露虹膜。分别检查左右开、合、中间态，并核对编辑器与导出坐标符号。

## 眨眼：保持眼睛内容，安排覆盖

本轮实际匹配的 22 段 blink 都使用 **position**，通过匹配皮肤/毛色的眼睑移出覆盖眼区，再缩回；没有以 scale 压扁整个虹膜和高光的实例。该结果限本次样本，不意味着整个模组绝无缩放式眨眼。

- Eevee：长度约 0.16667 s，眼睑局部位移 [0,0,-0.1] 从 t=0 保持到 0.125，再回到 0。起点已经闭眼，不是假定的“睁→半闭→全闭”。
- Lucario：左右分别含 [±0.1,0,-0.1]，与转角覆盖有关。Treecko 沿侧向眼面法线运动。不要将所有眼睑统一沿世界 Z 移动。
- Braixen 的约 0.125 s 片段时序不同。观察窗、首次闭合和保持时长按实际轨道解释。

制作新角色时，优先让眼睑遮挡/显露原眼纹，独立组织闭眼线；不要把缩放整眼当无需参考的默认方法。若明确选择卡通挤压，检查中间态的瞳孔、高光变形是否符合用户目标。开、闭、中间态都要检查，跨面眼需同时覆盖正面与侧面。闭眼线方向也应延续眼角关系。

Shinx/Luxray 的所选目录未发现 blink，但有眼睑结构；不据此断言运行时不会眨眼。Lucario 含 neutral/happy/sad 和多个眼睑，是表情资源候选，不是重复错误；实际使用取决于 poser/动画选择。

## 遮挡与材质例外

Ralts 的眼睛被头发遮住。先看原状态，再在隔离副本中临时隐藏遮挡以检查结构，明确标记该图为研究示意；不修改默认发型或擅自让眼睛穿透头发。

本轮主图只用了基础图；另查 14 张图层 PNG，Umbreon/Shinx/Luxray/Gengar 的眼部候选 UV 与发光图有非零 alpha 交集，Espeon 的对应候选区没有。不能将“有 emissive 图层”等同“眼睛发光”，也不能用基础图截图证明运行时亮度。基岩版新角色是否发光仍由参考和目标材质决定。

## 眼部验收与本项目反例

迪莫 v2 被用户否定。参考是饱满圆眼配斜上缘；v2 的 7×9 模板把上缘与瞳孔连成大的尖黑块、灰紫部分挤在底端，并通过整眼 Y 缩放眨眼。其 UV、矩阵、关键帧、脚底检查即使通过，也不能证明眼神合格。不能把已导出或已播放的结果标记为美术验收成功。

用户已反复不满意眼睛时，下一次应优先做局部对照：保持同脸型、同视角、同像素密度，比较少量眼型方案，明确改变的是上缘、瞳孔、虹膜还是眼距；需要改脸型时分开对照。先解决参考符合度，再扩大到整模。用户要求当前只研究时，不修改已有眼睛。

检查顺序：原像素 → 正面/斜面头部近景 → 正常观察尺寸 → 开/闭/中间态。若眼距、视线、下缘、上下眼角或跨面对应与参考冲突，就继续局部修正，不能用加色、提高分辨率、检查器通过或“更像 Cobblemon”代替解释。

## 可复用研究工具

`scripts/study_eyes.py` 从既有 corpus manifest 选择物种、登记眼骨与候选 blink、哈希来源；不自动把候选字段判断成审美结论。`scripts/inspect_eyes_blockbench.js` 通过 MCP 隔离导入，导出四视角、实际 UV 与 5 点 blink。名称筛选未命中时核查 head；出现遮挡需人工补充，报告不能谎称已见到被遮挡眼睛。

示意命令：

```text
py -3 -X utf8 scripts/study_eyes.py prepare --out <新研究目录> --manifest <120轮manifest> --manifest <200轮manifest> --species eevee,shinx,meowth
```

MCP 中设置 `window.CB_EYES_OUTPUT`，读取并执行原生脚本；`cbEyes.run(start,count)` 分小批运行。完成后实际查看图像并以补丁撰写 `visual-notes.json` 与 `findings.md`，复制来源许可到报告目录；运行 `layers`、`report`、`verify` 模式。报告图像、候选结构数据不放入 Skill；原项目现场和原资产只读。
