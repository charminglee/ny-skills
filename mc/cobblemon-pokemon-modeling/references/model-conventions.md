# 模型约定

## 格式与坐标

- 目标语料使用 Bedrock Geometry JSON，`format_version` 为 `1.12.0`，主体位于 `minecraft:geometry`。
- `description` 至少维护唯一 `identifier`、`texture_width`、`texture_height` 和合理的 visible bounds。
- 模型 identifier 通常为 `geometry.<species_or_form>`；不要保留 `geometry.unknown`。
- 根骨骼使用物种或具体形态名。其下通常设置 `body`，再按运动依赖拆成 torso、head、四肢、尾、翼等。

## 造型语言

- 先用少量矩形体建立头身比例和主轮廓，再用旋转块、分段与零厚度平面补充辨识特征。
- cube 的 size 优先使用整数。细微轮廓校正放在 origin、pivot、rotation 或很小的 inflate 中；不要用大量随机小数制造不必要噪声。
- 零厚度平面适合毛尖、羽片、叶片、耳尖、爪尖、牙齿、翼膜和火焰截面。选择零轴应与平面实际朝向一致，并从正反视角验证 Cobblemon 渲染器表现。
- 平面可以通过旋转和分段组成清晰的阶层轮廓，但不要堆叠大量近共面片模拟光滑曲面。
- `mirror` 适合对称肢体和对称表面；眼睛、花纹、毛流和性别/形态差异在镜像前必须核对方向。
- `inflate` 只用于层叠、避免可见共面或轻微轮廓修正。眼睑、眼球或外覆层常见 0.01/0.02 一类小值；大值需有视觉依据。

## 骨骼与运动

- 父子关系按运动传播建立，而不是按空间接近程度建立。
- 轴心放在真实转动中心：下颚关节、肩/髋、膝/肘、尾段根部、翼段连接处。
- 眼睛、眼睑与下颚需要动画时使用独立骨骼；左右命名保持 `_left` / `_right` 一致。
- 长尾、颈、触手、翅膀或毛束按必要自由度分段，常用递增后缀如 `tail2`、`tail3`。
- 保留已有动画引用。改名、换父级或移动 pivot 后，检查 animation 和 poser 中所有对应骨骼名。
- locator 只按系统用途添加，并采用语义名称；特效发射点、攻击点和相机/目标点要在关键姿态中验证。

## UV

- 默认使用 Box UV，起点使用整数像素坐标，PNG 实际尺寸与 geometry 的 texture 声明一致。
- 贴图岛尺寸应与 cube 局部面尺寸对应，避免拉伸；旋转 cube 不改变其局部面所需像素跨度。
- 修改几何尺寸后重新核对 Box UV 占用范围。不要只扩大 PNG 而忘记更新 geometry 声明，也不要只移动 UV 而遗漏普通/异色/图层贴图。
- 零厚度平面的有效面和 UV 方向需要视觉检查；透明边缘不等于 UV 正确。
- 逐面 UV 在格式上可能合法，但偏离该版本语料。只有实际需求足以抵消维护成本时采用，并记录偏离原因。

## Blockbench MCP 验收

通过 MCP 至少检查：正面、侧面、背面、三分之四视角；静止姿态；动作极值；左右对称；眼睑和下颚；平面背面；UV 预览；纹理尺寸声明。导出后重新读取文件，不把编辑器操作成功当作最终交付成功。
