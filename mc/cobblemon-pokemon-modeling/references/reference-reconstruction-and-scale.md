# 三视图重建、连接修正与视觉尺度

来自 Astral Fox、Plumeleaf 和迪莫的用户迭代。这里提炼决策方法，不是所有宝可梦都必须遵循的外形、尺寸或材质模板。

## 同一部件跨视角对应

- 正面和侧面都能看见眼睛，可能因为同一只眼睛位于斜向脸面，不能直接生成“正面两眼 + 侧面两眼”。先用正面、侧面、斜侧面确认部件身份、脸面夹角和遮挡。
- 棱锥式或楔形脸要由脸面、鼻梁和逐渐收拢的口鼻共同构成。仅把眼睛贴到方脸两侧、或仅缩鼻头，不能恢复参考的脸型。
- 眼形、外眼角倾斜、虹膜/瞳孔方向和黑色边框共同影响神态。先检查脸面与眼睛承载面的方向，再调整图案；不要用高分辨率眼睛掩盖错误几何。
- 缺失的下颌后段、下颌与上吻间的开口、头颈间隙是不同连接问题。闭口参考不应因后段补齐就保留意外张嘴缝隙；从侧面和仰斜角检查。

## 连接、薄片与外露共面

- 块体“包围盒重叠”不证明轮廓连续。旋转块需看世界空间实际表面，并用多角度图像检查可见缺口。
- 前胸鬃毛不能只在身体前方悬挂一张毛片；若参考需要体积，用最少的根部/连接体积接到本体，并挂到合适的运动父级。连接块不能在转头或呼吸时与胸毛分离。
- 毛片和耳片要保持参考的宽扁轮廓。用户要求薄实体时，不用厚尖刺、交叉卡片或大量碎块替代。
- 先区分真正外露的竞争表面与内部遮挡面。对外露共面可局部微调厚度、缩放或位置，保留重叠连接；不要为了使检测计数为零而移动所有内部接触面。
- 分段薄片的宽面尤其容易处在完全相同的前后平面。可让外段比根段略薄，避免同一深度；微调量取决于整体尺度和运行目标，不固定套用某个数值。
- 几何微调后冻结或重新核对原 UV。保留宽面像素和毛流；窄边采用分数采样时检查导出取整、有效纹理和保护边。Box UV 对小尺寸的取整不能成为错位、串色的来源，必要时改成逐面 UV。
- Java 预览或游戏中不明显的闪烁，不能推断在 Bedrock 中也无影响。目标变更时重新检查材质、alpha、背面和相机转动下的表现。

### 腿根嵌合不等于外表面可以共面

- 迪莫 v5 的四腿根部嵌入躯干，但左右外侧面与躯干侧面完全共面，后腿后表面也与躯干背面共面。内部体积重叠维持连接是合理的；外露的同深度面争抢显示才是本次要修复的问题。
- 检查世界空间中面法线、平面位置与交叠面积，并从侧面、背面及后下斜角查看。只有同平面而没有面积交叠的相邻边，不应直接判作闪烁；旋转组件不能只比较局部 from/to。
- 对该结构，将四腿外侧面和两后腿后表面微量内收即可。保持腿长、脚底、内侧边、轴心和骨骼关系，腿根仍嵌入躯干；不要全块等比缩小、缩短腿造成悬空，或为消除数值交叠而把腿根截到身体边界。
- 本例内收 0.025 最终模型单位，保留约 1.178 单位的腿根嵌入深度；UV/PNG 未变，宽向密度约增加 2.2%、后腿纵深约增加 1.4%。这是该尺度下的局部修正例外，不是通用偏移量或允许拉伸所有 UV 的规则。
- 修前保留现场快照，修后确认只改目标端点；检查 UV、纹理、骨骼和动画未被工具自动更改。更新工程、geometry、预览和交付包，避免用户加载旧包。若已有动画需复查运动极值；静态任务不因此擅自制作动画。
- 该修正已在编辑器侧面及后下斜角检查，未做游戏内验证。不能由单张静态截图保证所有镜位及运行时均无闪烁。

## 人物对照与整体缩放

1. 约定测量端点：脚底到头顶、耳尖或叶尖；每个对象按自己的接地基线量高，不能直接比较两者最高点的画面 Y。说明透视、姿态和透明边缘造成的估算误差。
2. 参考实高 `Hc = H人 × 角色像素高度 / 人物像素高度`。若按玩家外观对照，目标模型高度 `Uc = U玩家 × Hc / H玩家`。别将 visual 模型高度、16 单位/格和碰撞箱高度混为一套尺度。
3. 选择一个负责最终大小的环节：几何烘焙缩放或已授权的运行时 scale。避免模型已缩小而实体/poser 再缩一次；不因调整外观而擅改碰撞箱。
4. 几何缩放时同步处理 cube from/to/origin、骨骼 pivot、inflate、相关 locator、visible bounds 和全部 position 动画。旋转保持原样，维度无关的 scale 通道一般不乘几何缩放因子；检查带表达式或 Bezier 位移的轨迹。
5. 用户只要求调整大小时，保留 PNG 像素和图案采样。先缓存 Box UV 的实际逐面映射再转换或缩放，避免自动展开跟着几何缩小而裁坏图案。整体密度会变成原来的 `1/s`，应明确报告，不声称仍是原先的像素/单位。
6. 在统一镜位、投影和地平线上比较玩家示意与新模型；脚爪、耳叶、转头和尾部的动态范围也要复查。使用实际几何顶点测量，排除隐藏选择线和 gizmo。

## 已验证案例的边界

- 用户给定参考人物 1.6 m、Steve 1.8 m。以标准玩家模型 32 个视觉单位标定：Astral Fox 含耳尖估算约 1.75 m → 31.1111 单位；Plumeleaf 含叶尖约 1.83 m → 32.5333 单位。它们不是通用生物尺寸，也不是自动生成的碰撞箱。
- Astral Fox v4 相对此前工程整体缩放约 0.5148，Plumeleaf v8 约 0.4329；保留贴图像素及原图案，位移动画同步缩放。不要把这些系数应用到其他基线。
- 这些版本做过 Blockbench 与导出复核，没有 Minecraft Bedrock 游戏内运行验收。原有薄片/材质的目标环境表现仍须实际验证。
