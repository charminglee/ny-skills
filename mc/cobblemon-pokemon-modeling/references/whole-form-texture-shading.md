# 整体结构重绘：从材质样品到连贯体积

用于全身材质初贴后的整理、样品裁片造成的杂乱、跨面明暗断裂及原模组着色研究。核心区别：**样品给色阶与材质语言，形体决定明暗位置。** 这是从成品研究归纳的工作方法，不是对原作者绘制工序的声明。

## 证据与范围

本地 Cobblemon Forge 1.5.2+1.20.1 的已有 120+200 语料重分析，共 320 个不同物种，非新增 320 只、非随机抽样：

- 320 次隔离 Blockbench 导入；绑定姿势，基础 PNG，正/侧/背/斜四视角各开关一次编辑器面光照，共 2,560 个渲染视图。
- 查看全部 40 张联系表覆盖的 320 只正侧背外观，另对 24 只做主头/躯干实际 UV 细审；不等于每个视图、像素和动画都精审。
- 记录 64,742 个有面积且有 UV 的面；63,146 个面在基础图采到 alpha≥128 的像素。包含内部/隐藏面及共用 UV，不是可见表面计数。
- 49 只的基础分支带未合成图层，其他条件分支也未重现。不得用缺层外观判断最终配色、发光或透明表现；没有游戏运行时验证。
- 研究目录为该任务的 `outputs/cobblemon-shading-study-320/`：`manifest.json` 保留 1,030 个源文件哈希；`surfaces/`、`records/` 可复查面数据；`visual-notes.json` 记录人工观察；`report.html` 汇总截图与结论。移动 Skill 后此本地报告可能不随附，不能声称重新检查过未获得的证据。

- 小猫怪主头正面 9×8 只有 3 色，单一主色占约 78%；侧面 5 色、后面 4 色。伊布和乌波正面主色各约 69%。**安静的大色块也是设计**，不能用全身均匀加色、加碎纹来证明丰富。
- 可达鸭头后面仅 2 色，仍和其他面形成连贯明暗。少色不自动失败，多色不自动通过。
- 叶伊布躯干侧面同色相候选上/下部差约 +12.16 L*，前端却约 −17.76 L*，上方邻近头颈连接。这支持按局部遮挡组织暗区，而非全身统一高度渐变；并非验证过的真实 AO。
- 土狼犬黑口鼻/胸与浅灰背部是固有分色，不能为“正面平均更亮”抹掉。可可多拉白甲与深肤同属自动 neutral 色相桶，但不是同一材质。
- 风妖精细图自动选中棕色核心而非棉团；伊布的最大躯干块是奶白毛领，卷卷耳的躯干核心多被毛团遮住。按名称/面积选块不等于材质语义分割。
- 吼鲸王较密纹理仍沿整个躯干组织宽明暗带；密度控制与明暗组织是两项独立判断。

批量对向面候选中，上/下 3,606 对、中位差 +4.46 L*；前/后 3,592 对、+3.71 L*；单面上/下部 13,528 组、+4.50 L*。筛选使用近轴法线、最小像素数和共同 HSV 色相桶，不是真正同材质识别；内部面、共享岛和同物种多面重复计入。只支持“常有成片方向明暗”，不转成物种比例、统一亮度倍率或美术评分。

## 初贴后的整体结构重绘

1. **固定本次变量。** 默认保留几何、密度、UV 与图集大小；先记录共享 UV、镜像和材质边界，保护眼睛、口鼻、固有花纹与 alpha。若共享岛阻止必要的独立明暗，应指出并按授权再改 UV，不能偷偷连带修改另一部位。
2. **画整只的明暗计划。** 按连续体积而非 cube 数量分组，识别头、颈、躯干、肢体、尾等表面方向和真实遮挡。先看哪些宽区域亮、中、暗，再看毛流、叶脉等细节；不是每个面中心一个高光、四周一圈黑边。
3. **先重排大色域。** 初贴继承样品色阶，结构重绘重新决定它们的面积与位置。让亮域/中间调/暗域沿整个形体延续，弱化没有形体或材质意义的孤立亮点、棋盘碎斑和重复条带。
4. **再画自然像素过渡。** 使用相邻色阶、逐步变化的色块面积与有意的阶梯边界。只在体积转折、毛束/褶皱等需要处增加小色簇，保留较大的稳定主色面；不靠模糊、抗锯齿、随机抖点或放大图集实现“自然”。阴影不统一加灰黑，冷暖倾向按材质和参考决定。
5. **检查真正的邻接面。** 利用模型方向、UV 翻转和镜像确认头顶→侧脸→下巴、正脸→侧脸→后脑、颈→躯干等过渡。连续表面的接缝可用共同中间色衔接；实际锐折、遮挡、材质/花纹分界仍可保留有意对比，不能强行抹平所有边界。
6. **同条件验收。** 对照初贴和重绘，固定几何、UV、姿态、镜位及预览设置，分别看关闭/开启编辑器光照、近景/正常距离；灰度辅助看大明暗，彩色确认固有色与视觉焦点。检查原始 atlas 与实际面像素，随后核对非目标区、alpha、嵌入 PNG 和独立导出。

此步骤不授予模型或 UV 的额外修改权限。用户只要求研究时只产出证据与流程，不重绘当前角色；局部材质修补也不自动扩成全身重画。

### 较大体型的后续修正

后续40只定向复查与Plumeleaf v9被用户否定的记录见 [large-creature-materials.md](large-creature-materials.md)。整体重绘不等于大渐变加去噪：大明暗与小细节之间需要有明确的毛束、羽列、叶脉等中等尺度结构。不能因强调安静大色块而抹掉有效材质，也不能把材质丰富度再次简化为每面最低色数。该补充不是新增40物种，也不证明v9已成功。

### 迪莫的具体应用方向，尚未执行验收

按本次用户要求，在同一材质内优先安排额头/上脸较亮、侧脸中间调、下巴/颈下较暗，正面偏亮、背面偏暗。蓝毛、奶白脸胸、黄纹分别保留固有色和层次，不把眼睛/标志花纹一起整体压暗。额头到下巴需跨真实脸型连续过渡，不直接复用样品中随机位置的亮暗。

这不是所有物种的固定照明公式。本轮研究没有重绘迪莫，不能把新流程描述为已经改善了迪莫或获得用户认可。

## 复用研究脚本

- [../scripts/study_shading.py](../scripts/study_shading.py)：Python 3 + Pillow。读取已有 corpus manifest，去重物种并记录哈希；原生面采样、联系表、详细 UV、报告与源文件复核。
- [../scripts/inspect_shading_blockbench.js](../scripts/inspect_shading_blockbench.js)：在 Blockbench MCP 内加载，使用独立临时项目，保存原现场快照并恢复原项目。执行前发现工具、确认项目及来源许可；原模型/PNG 只读，测试贴图解除路径关联。

先准备新的独立输出目录（不要覆盖别次研究的快照），再通过 MCP 执行原生采样：

```text
py -3 -X utf8 <skill>/scripts/study_shading.py prepare --manifest <120语料>/manifest.json --manifest <200语料>/manifest.json --out <研究目录>
```

```javascript
window.CB_SHADING_OUTPUT = 'C:/absolute/research-output';
eval(require('fs').readFileSync('C:/absolute/skill/scripts/inspect_shading_blockbench.js', 'utf8'))
```

随后分批 `await cbShade.run(start, count)`，`start` 为零基索引；脚本跳过已有成功记录。同一 Blockbench 项目的调用串行执行；每批结束核对回到原 UUID。用适量批次维持状态可检查，不启动未经跟踪的并发任务。当前实现要求带 `SHADE` uniform 的原生材质，否则报错，不静默把普通着色冒充关闭光照。

```text
py -3 -X utf8 <skill>/scripts/study_shading.py analyze --out <研究目录>
py -3 -X utf8 <skill>/scripts/study_shading.py contacts --out <研究目录>
py -3 -X utf8 <skill>/scripts/study_shading.py details --species eevee,shinx,leafeon,wooper --out <研究目录>
py -3 -X utf8 <skill>/scripts/study_shading.py verify --out <研究目录>
```

`contacts/details` 当前采用 Windows Arial 字体；迁移平台需调整字体路径。`details` 仅选直接命名头/躯干下最大的块，必须人工确认材质身份。实际查看图后编写 `FINDINGS.md` 和 `visual-notes.json`（`pages` 为按页观察字符串列表，`details` 为物种名到细审观察的映射），再运行 `report --out <研究目录>`。不要自动生成“已观察”笔记来替代看图。

原生导出/图像取样仅作本地证据；研究报告保留源资产许可与作者归属。Skill 只携带规则与研究工具，不携带原模型、贴图或 UV 裁片；需要复制或发布时另读 [licensing.md](licensing.md)。
