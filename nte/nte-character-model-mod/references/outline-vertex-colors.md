# 描边变淡：顶点色编码与修复步骤

适用于替换网格后，身体、脸部、发梢等描边变淡，而部分衣物描边仍正常的情况。依据 2026-10-29 明音凛 JK 去布料案例整理；通道用途及材质参数须以目标角色为准。

本记录说明已证实的顶点色偏差及源文件修复方法。虚幻编辑器内的导入、设置、烘焙和验证仍由用户手动完成，不能据此自动启动编辑器、UE MCP 或 Commandlet。

## 先分清症状

| 现象或证据 | 优先检查 |
| --- | --- |
| 中间控制值改变，但 0/255 不变；不同材质的描边受影响程度不同 | COL0 的线性/sRGB 转换 |
| 原版材质路径、资源类型或 OutlineOverlayMaterial 不一致 | 原版材质实例及描边引用链 |
| 去布料处仍有局部暗带或硬接缝 | 漫反射残影、几何和自定义法线，不能只靠描边设置处理 |
| 整体拉成细线、塌缩、面片错位或大面积缺失 | 单位、根骨参考缩放、绑定矩阵、骨骼索引与权重；独立排查 |

不要先把所有材质的描边强度统一调大。若控制数据或引用已改变，调强度会掩盖原因，也可能把原本正常的衣物描边加粗。

## 已证实的编码问题

游戏网格的顶点色可能承载描边等控制数据，不能仅凭“颜色层”名称将其当作显示颜色。本例从原版和旧成品的实际渲染顶点色中读到以下对应关系：

| 原版通道值 | 旧成品通道值 |
| --- | --- |
| 76 | 148 |
| 128 | 188 |
| 50 | 122 |
| 100 | 168 |
| 150 | 202 |
| 0 / 255 | 0 / 255 |

这些中间值的变化符合额外施加 sRGB 编码的结果。常用中间值的身体/脸部，以及发梢的部分控制值因此偏离原版；端点值较多的区域变化较小。**不要把本例推导成所有角色都由同一 RGBA 通道控制描边宽度或颜色。**

### Blender 中容易混淆的两个读法

- `attribute.data[i].color` 是线性表示；`color_srgb` 是 sRGB 表示。先确认数据来自哪一种读法，再与游戏中的整数 RGBA 比较。
- `BYTE_COLOR` 的存储量化会影响中间值。本例中，某值的 `color_srgb` 为 148，而 `color * 255` 约为 75.515；按 LINEAR 导出后仍可能得到 75，而非原版 76。
- 若目标是精确保留原版控制值，可使用同名、同域的 `FLOAT_COLOR` 属性，按原版整数 `RGBA / 255` 写入线性 `color`，再以 LINEAR 导出。不要把原版控制值写入 `color_srgb` 后又做一次转换。
- 不要只修 RGB 后顺手重置 Alpha，也不要给未匹配点统一填白色。Alpha 和接缝两侧的不同取值同样属于原始数据。

## 修复步骤

### 1. 建立实际数据基线

1. 备份当前 `.blend`、FBX 和用户提供的现有产物；保留内嵌图像、隐藏状态与未保存编辑。不要用较旧的外部 PNG 覆盖已绘制的内嵌贴图。
2. 从原版及实际问题产物读取同一 LOD 的 Section→材质、位置、全部 UV、RGBA、法线及骨骼引用。核对产物身份，不把 Backups 中某个文件自动视作游戏当前加载版本。
3. 源顶点、FBX 顶点及渲染顶点会因 UV/法线接缝拆分和重导入重新排列，不能按数组下标直接复制颜色。用材质分区、同坐标空间的位置、UV 和接缝信息建立对应关系；必要时结合全部 UV 与原有颜色区分同位置拆点。
4. 按材质分区统计偏差，特别检查原版中间值是否变成上表中的 sRGB 值。只比较全模型平均值或材质槽数量不足以定位。

### 2. 只恢复目标控制数据

1. 对可靠匹配的角点/顶点回用原版 RGBA。新增补皮和移动部位按其来源、同一皮肤分区的插值或既有线性值处理；记录未匹配范围，不跨衣物/皮肤或 UV 岛借用数据。
2. 若确有八位往返误差，在副本中将 `COL0` 改为 `FLOAT_COLOR`，保持原来的属性名和域。本例为 `CORNER`；其他模型先核对，不硬套。
3. 在浮点属性中以 `R/255、G/255、B/255、A/255` 写入线性值。已经是正确线性数据的模型，不再重复做 gamma 反变换。
4. 比较修改前后受保护数据：顶点位置、拓扑、全部 UV、其他颜色层、全部形态键、骨骼层级、权重、材质分区和自定义法线。描边数据修复不应顺带重算法线、重绑骨骼或改变形状。

### 3. 导出和交付 FBX

- 使用官方导出器，顶点色选项明确为 `colors_type='LINEAR'`，不要依赖默认值。可随修改清单写明“COL0 为线性控制数据，禁止再次按 sRGB 编码”。
- 其他导出选项沿用已核对的配置，保留独立材质分区、所有 UV/颜色层、形态键和骨骼；导出后重新读取 FBX 检查实际值，而非只检查选项。
- 单位与绑定遵循主技能的厘米空间要求。历史导出脚本即使修正了顶点色，也不能不经核对就复用其米制单位处理；不要在此次修色时额外引入根骨 100 或 0.01 倍缩放。
- 交付 `.blend`、FBX、原版引用基线、匹配/未匹配范围和修改清单。源文件检查通过不等于编辑器或游戏验证通过。

### 4. 交给用户手动核对的编辑器事项

- 导入实际修改的顶点色时，核对 **Vertex Color Import Option = Replace**，避免 Ignore 继续沿用旧数据，或 Override 把控制值改成常量。
- 本例已有连续的源自定义法线，应采用 **Import Normals and Tangents** 并保留它们，避免重新计算后再次出现胸下接缝。其他模型按其实际法线基线处理，不把重算法线当作通用描边修复。
- 核对材质对象完整路径及资源类型，并检查原版材质的描边覆盖引用（如 `bOverrideOutlineOverlayMaterial`、`OutlineOverlayMaterial`）。同名普通 `Material` 不能自动视为原版 `MaterialInstanceConstant`。
- 本例暂存网格曾有七项预览材质导入类型与原版不同；这是引用一致性问题，不能据此声称它是描边变淡的唯一原因。只恢复基线明确的类型，不批量把所有 Material 改为实例。
- 工程预览占位材质不加入模组覆盖清单。需要编辑器处理时，把具体差异和所需产物交给用户；收到对应烘焙产物后才继续离线检查或 retoc 打包。

已获授权且仅需离线修引用时，参见 [模型与 FBX 记录](model-fbx-notes.md) 的相应章节；沿用原索引、只改包头的修复应验证 `.uexp` 不变及相关偏移正确。

## 验证范围与本例未解决问题

按实际完成的层级记录结果：

1. **源文件/FBX**：线性控制值、原始数据保留、厘米尺寸、根骨参考缩放和绑定关系。
2. **用户提供的烘焙产物**：真实 ColorVertexBuffer、材质路径/类型、UV、法线与形态目标；不能只检查 FBX 中有 COL0。
3. **容器**：retoc info/list/verify、Zen→Legacy 回读和必要的正文校验。这能证明容器可读及内容一致，不能证明动画绑定或画面正确。`UnknownPackage/UnknownExport` 可能来自缺少外部解析上下文，不应当作真实引用重新打包。
4. **游戏反馈**：用同姿态、距离、光照及对应 LOD 对比描边，并确认动画、移动和表情没有新增异常。由用户提供实际反馈，未经实测不标记视觉修复成功。

本例离线确认了控制值回归、83 个形态目标及容器回读，**没有完成游戏内描边修复的验收**。2026-10-29 用户补充截图可见身体/面片大范围错位、细长条状拉伸和缺失；截图对应包版本及根因尚未核对，不能归因于 COL0，也不能写成已解决。

若出现这类变形，暂停“描边已修好”的结论，先核对单位、根骨参考缩放、绑定矩阵、骨骼索引/权重和动画驱动。静态尺寸约 172 厘米、骨骼数量/名称一致、颜色恢复或 retoc verify 成功，都不足以排除绑定错误。相关单位与根骨故障见 [模型与 FBX 记录](model-fbx-notes.md)。
