# 只删面模型的原生索引修改

本次验证输入为用户修改的 YuCong 身体模型；该流程有明确前提，不是通用 SkeletalMesh 导入器。

## 适用性

先对原版母本和用户文件做精确差异检查，后台 Blender 打开编辑模式保存的文件后先切到对象模式，再读取 UV 等网格数据。

允许继续的条件：

- 修改后的三角面是原版面的子集；保留部分坐标、UV、权重、材质分区、法线/颜色及变换、骨骼和绑定保持一致。
- 使用坐标、逐角 UV、权重和保留绕序的三角面键匹配，允许删点后顶点重编号。只比较无序坐标会把反向面或重叠面混淆。
- 检查形态键、布料映射及其他依赖拓扑的数据。当前案例无形态目标、各 section 的 ClothMappingDataLODs 为空；复杂映射未按本方法验证。
- 没有活跃 Nanite 网格。`NaniteResources != null` 不足以判定启用：本次资源对象存在，但 `NumClusters=0`、`NumRootPages=0`。有实际 cluster/page 数据时不能只修改传统索引后宣称覆盖完成。

新增/移动顶点、重拓扑、权重变化或上述条件不满足时，不用删面方法替代用户实际编辑。说明观察到的差异及还缺少的写回能力。

## 建立删除集合与 LOD 对应

1. 原版 `.uemodel` 保留全部 LOD；用户 `.blend` 一般是 LOD0。记录匹配、删除和不匹配面数，确认没有未知新增面。
2. 用共享空间位置连通性检查删除区域。本次恰好是 5 个完整独立部件，可以跨 LOD 对应。
3. 对其他 LOD 结合 UV 和空间位置匹配原版 LOD0 表面：UV 平面 BVH 找候选面，重叠 UV 用重心映射后的 3D 距离区分。
4. 按每一级的独立几何部件检查分类。本次各部件的保留/移除判断完全一致，未出现同一部件混合分类。
5. 出现混合部件、最近表面歧义或大偏移时，检查对应关系；不能用无依据多数投票扩大删除范围，也不能静默保留低 LOD 中的原衣物。

只修改 LOD0 可能使远景重新显示原版部件。不要未经判断强制 LOD0 或替换 LOD 配置来掩盖对应问题。

## 定位原生索引

通过 CUE4Parse 读取 `USkeletalMesh.LODModels[lod].Indices.Buffer`、section、顶点数与其他原生数据。

- 确认该索引顺序与原版 UEFormat 三角面顺序的关系；本次完全一致，其他案例不能假设。
- 为每级生成按真实宽度编码的完整索引字节数组，在原始 Zen 包/附属块中定位；验证长度、索引范围、唯一匹配和原字节一致。
- 本次 5 级都是 UInt16，但文件布局、索引宽度、数据所在块和偏移均须重新定位。不能复用 YuCong 偏移。
- 确认实际绘制使用的索引及相关拓扑数据都已覆盖。保留原始块副本与摘要。

## 原位修改

将已删除的面 `(a, b, c)` 写成 `(a, a, a)`，保留原始数组长度、顶点缓存、三角面槽位和文件大小。重复顶点构成零面积面，不产生可见几何。未删除面的索引逐项不变。

这属于绘制面消隐，原生顶点数和三角面槽位数仍可保持原值。不能在报告中将其说成原生缓存已缩减到 Blender 删点后的顶点数。

修改后对每个块计算差异位置，要求所有变化都在已定位的索引数组内。所有非索引字节、包内原始引用、section 布局和 Native buffer 均保持一致，再按单模型白名单封装。

## 验证

- `retoc info/verify` 通过，包内只有目标网格与附属块。
- CUE4Parse 从新容器回读各级索引，与计划索引逐项一致。核对 Skeleton、PhysicsAsset、材质槽、骨骼及依赖链接。
- 原版与修改包的顶点位置、法线、UV、颜色、蒙皮缓冲和 section 不变。
- 回读模型到 Blender：排除计划消隐面后，用有朝向的坐标/UV/权重面键与用户文件比较，重复面的数量也必须一致。
- 各低 LOD 保留集合和移除集合与映射结果一致；没有把删除区域转移到错误几何层。
- 保存静态验证记录。游戏运行、布料物理、技能状态和 LOD 切换效果仍需实际游戏测试，不能由容器校验替代。
